# 字趣 · 甲骨构字记

一个以甲骨文为题材的**汉字文化游戏平台**。
首个玩法「甲骨构字」已上线：翻出契文，用甲骨文构件拼出它，在卜问与质问里读懂商代。

> 本项目前身是单文件原型《字从契来》。现按平台化思路重构：
> **新玩法是一个模块文件，不改动平台其余部分。**

---

## 这是什么

| | |
|---|---|
| **形态** | 纯静态网页（H5）。无需服务器、无需构建、无需数据库 |
| **运行** | 双击 `index.html` 即可本地打开；上传到任意静态托管即可在线访问 |
| **数据** | 全部保存在本机浏览器（`localStorage`），**不上传任何服务器** |
| **依赖** | 零。没有框架、没有 CDN、没有外部字体与图片 |

**为什么不用 ES module**：`import` 在 `file://` 下会被浏览器的 CORS 策略拦住，
必须起服务器才能调试。这里改用传统 `<script>` + 全局命名空间 `App`，
**既能拆文件、又能双击打开、还能直接传 GitHub Pages。**

## 玩法二：殷商王邑（图卷 · 点击即学）

**一张三千年前的王邑图卷，点画上的实物，认那个甲骨文。**

底图是一整幅水墨图卷（`assets/wangyi-map.jpg`，1800×907）。画上有远山、
河流、田亩、城邑、牲畜、弓箭手、青铜鼎……

**画上不画任何字形标记**，保持画面完整。真正的可点之处是【隐形热区】——
位置对应画里那样东西本身：山字贴在山上、鼎字贴在青铜鼎上、弓字贴着弓箭手。

| 分区 | 数量 | 内容 |
|---|---|---|
| 天象 | 4 | 日 月 雨 火 |
| 山川 | 9 | 山 水 川 泉 谷 丘 土 石 田 |
| 草木 | 6 | 木 林 竹 禾 米 屮 |
| 禽兽虫鱼 | 9 | 牛 羊 犬 豕 鱼 隹 虎 鹿 虫 |
| 人居器物 | 33 | 邑 郭 门 宀 鼎 缶 皿 酉 弓 矢 戈 衣 人 目 口 女 子 足… |
| | **61** | |

### 怎么用

1. **点画上的实物** → 出学习卡：大字形甲骨文、今字、分区、一句象形说明
2. 鼠标悬停时，该处会浮出甲骨字形小牌——这是鼠标用户发现可点之处的方式
3. **触屏没有悬停**，所以有「显示可点处（61 处）」开关：打开后热区显形为虚线圈
4. 认过的实物在角上点一枚很小的绿点，顶部进度条记「已认 N / 61」
5. 学习卡下方「接着认」给相邻几个字，也可按「上一个 / 下一个」顺着看
6. 键盘可用：Tab 聚焦 + 回车打开

> 底部另有两个入口：**答题练习**（原拆字/配对/卜辞关卡）与
> **原有的单字选构练习**。图卷是主线，练习是可选加餐。

### 数据

全部在 `js/core/levels.json` 的 `map.zones[].objects`，**代码不写死任何字表**：

```json
{ "id": "land", "name": "山川", "note": "山水川泉谷丘土石田",
  "objects": [
    { "char": "山", "x": 135, "y": 225, "r": 74, "meaning": "三峰并立" }
  ] }
```

- `char` 字 / `x,y` 热区圆心 / **`r` 热区半径**（大小对应那样东西在画上的实际大小：
  山脉 r=74，陶罐 r=26）/ `meaning` 象形说明
- 坐标是在 **1800×907 的底图像素空间**里手工读图定的，与 `viewBox` 一一对应
- 增删实物只改这里，然后跑 `python dev/_build_object_map.py`（带自检）
  与 `python dev/_build_leveldata.py`（重新内联）

### 加实物时的自检（`_build_object_map.py` 会报，任一不过就退出）

| 检查 | 为什么 |
|---|---|
| 缺字形 | 引用了 `glyph-parts.json` 里没有的字，卡片会是空白 |
| 重复摆放 | 同一个字摆两次，会让人以为能点出不同东西 |
| 热区重叠 | 圆心距 < 半径和的 0.75 就报——两个热区叠在一起会点不准 |
| 越出画布 | 圆心跑出 `viewBox`，点了没反应 |
| 底图缺失 | 图片路径写错，地图会开天窗（**会直接中断生成**） |

### 换底图 / 重新裁图

`dev/_prep_map_image.py` 负责：裁掉右下角「豆包 AI 生成」水印 → 缩到 1800 宽 →
存为 `assets/wangyi-map.jpg`，并额外输出一张**带 100px 刻度的预览**
（`%TEMP%\map_grid.png`），用来读图定位新坐标。

换图后 `viewBox` 要跟着改（`_build_object_map.py` 里的 `VW/VH`），
所有热区坐标也得重新标——因为坐标是绑在底图像素上的。

### 底图出处与说明

底图由**豆包 AI 生成**，属个人非商用使用；右下角水印已裁除，
地图下方保留了一行出处说明（`map.bgCredit`）。

> 只把它当**画**用。字形一律用项目里那套真货（Li & Bian 数据集，CC BY 4.0）——
> AI 画的「甲骨文」一定似是而非，**拿它当字形就是污染数据**。

### 曾经走错的方向（留个记录）

这一节先后错了两回，都记在这：

1. **做成了「区块闯关」**：区块 → 关卡 → 答题，还有解锁闸门和拼图块点亮。
   方向错了——需求是"看图认字"，地图即教材、点开就学；闯关是在考人。
2. **把 61 个字形标记摆在画上**：会盖住画，也遮掉了甲骨文"象形"这个看点。
   现在是画保持干净、热区隐形。

### 白屏排查（线上打开是空白）

**30 秒确认**：在地址栏直接访问 `https://<站点>/css/theme.css`。

## 玩法模块的约定

新增玩法**只需新建一个文件**，放在 `js/modes/` 下，并在 `index.html` 里加一行 `<script>`。

```js
App.modes.register({
  id: 'your-mode',
  name: '玩法名',
  tagline: '一句话说明',
  desc: '展开说明',
  icon: '单',                 // 单字图标
  accent: 'var(--cinnabar)',  // 图标底色
  tags: ['单人', '计时'],
  minPlayers: 1, maxPlayers: 2,
  status: 'ready',            // ready（可玩）| wip（开发中）| planning（筹备中）

  data: {                     // 需要哪些数据，平台会准备好
    packs: [{ type: 'cards', role: 'main', label: '字包' }],
    assets: []
  },

  settings: [],               // 可选设置项声明（也可以自己在 mount 里画）

  // 平台给你一个空容器 host，以及一份上下文 ctx
  mount: function (host, ctx) {
    // ctx.primaryPack  已解析好的主数据包
    // ctx.packs        该模式可用的全部包
    // ctx.ui           共享渲染工具（el / esc / toast / signed …）
    // ctx.store        命名空间化存储
    // ctx.theme        读写主题
    // ctx.nav          跳转（home / modes / replay）
  },

  unmount: function (host) { /* 清定时器、移除 body 上的临时类 */ }
});
```

**平台保证**：
- 模式之间互不干扰（各自 `mount`/`unmount`，不共享全局状态）
- 离开对局时自动调用 `unmount`
- 内容包按模式声明的类型自动解析，模式不必了解存储细节

## 内容包（多类型）

平台不只服务「字包」。`js/core/packs.js` 里登记了四类结构，新类型加一条 schema 即可：

| 类型 | 结构 | 用途 |
|---|---|---|
| `cards` | `{ pieces:[], cards:[] }` | 字包（构件 + 字卡） |
| `quiz` | `{ questions:[] }` | 题库 |
| `atlas` | `{ entries:[] }` | 图鉴 |
| `script` | `{ chapters:[] }` | 剧本 / 章节 |

用户自建内容保存在 `localStorage`，可导出为 JSON 分发与备份。

## 设计与素材

### 视觉取向

参考《黑神话：悟空》一类"厚重东方 + 现代游戏感"的处理手法（深色底、材质层次、
雕刻感描边、戏剧性明暗对比），**但颜色与纹样一律回到甲骨本身**：

| 依据 | 用在哪 |
|---|---|
| **墨** `#1b1611` | 刻痕、正文 |
| **骨** `#efe4cd` | 载体、亮面 |
| **朱砂** `#a8321f` | 点睛、强调、主按钮（取自甲骨卜辞的"填朱"） |
| **青铜** `#8a6a33` | 少量点缀、描边 |
| **兆纹** `#8a7a5e` | 裂纹、分隔线 |
| 骨片轮廓（不规则八边） | 编号牌、放置槽、构件格 |

三套主题：**灼骨**（默认，深色）· **骨白**（浅色，出土本色）· **素色**（无纹理，阅读优先）。

### 字形素材与授权

页面背景纹样与标题字形来自 **真实甲骨文字形**：

- 数据集：[hanzi-glyphs-svg](https://github.com/zhouyongh/hanzi-glyphs-svg)
- 上游：Li, Qing-sheng & Bian, Yu-lin (2026),
  *Oracle Bone Glyphs: Parametric Vector Dataset (v0.3)*,
  [10.5281/zenodo.22467946](https://doi.org/10.5281/zenodo.22467946)
- 授权：**CC BY 4.0** —— 允许商用，**须署名**
- 本项目所做的修改：缩放、配色、合成为平铺纹样、编排为标题字形

署名已写入 `index.html` 页脚，**请勿删除**（这是授权条件）。

### 构件字形：`js/core/glyph-parts.json`

**61 个甲骨字形**，供拼字/拆字/配对三个玩法使用，同样出自上面这份数据集，
**CC BY 4.0，须署同一作者**。

- 内容：字 → `{glyphId, svg, bbox, sourceChar, unicode}`，SVG 内联（避免额外请求与 file:// 跨域）
- 画布：统一归一化到 100×100，按每个字形的实际路径坐标等比缩放并居中
- 署名与来源写在 JSON 的 `attribution` 字段里，随数据一起带走
- **重新生成**：`python dev/_gen_glyph_parts.py <上游稀疏检出目录>`
  上游仓库：`github.com/aylqs2025/oracle-bone-jgw-1203`（commit `5496ad5`）
- **不做分区索引**：早先曾按区块给字分组（landscape/creature/life），
  但那是按「单构件字」的思路建的；关卡改为「单字拆字」后，同一个字
  （如 日、月）既属于自然风光又是拆字构件，分组与实际内容脱节，
  还让拆字干扰项抽不到同域字。现只保留一张统一字表，
  哪些字用于哪一关由 `levels.json` 决定（内容与代码分离）。

已核对的两个坑：

| 构件 | 情况 |
|---|---|
| 门 / 贝 | 数据集以**繁体「門」「貝」**收录（glyphId 849 / 481），需按繁体查 |
| 囗 | 数据集**未收录**，但**不参与任何字卡**；借用「口」的方框形，JSON 内标 `isFallback` |

> 特别提醒：**不要手工编辑 `glyph-parts.json`**（文件首行已注明）。
> 它由脚本生成，手改会在下次重新生成时被覆盖。

## 开发自查

`dev/` 与根目录的 `_check*.py`、`_shots.py` 等脚本用于**在真实浏览器里验证**：

| 脚本 | 作用 |
|---|---|
| `_run_drive.py` + `drive.js` | 原有玩法（甲骨构字）：在 headless Edge 里走一遍全流程，回报状态与控制台错误 |
| `_run_wy.py` + `wy-drive.js` | 王邑闯关：验证解锁链、拆字与配对机制、未开放区块拦截 |
| `_gen_glyph_parts.py` | 由上游数据集生成 `glyph-parts.json`（含归一化） |
| `_build_leveldata.py` | 把两个 JSON 内联成 `_data.js`（file:// 下不能 fetch） |
| `_build_glyphcheck.py` | 生成字形对照页，含越界/过小检查 |
| `_syntax_probe.js` / `_verify_deploy.js` | 语法与部署资源大小写校验 |
| `_contrast.js` | 各主题配色对比度审计（WCAG） |
| `_cleanup_edge.py` | 安全清理无头 Edge（默认演练，`--kill` 才真关） |

> 这些脚本依赖本机的 Microsoft Edge 与 bundled Python，**不属于部署内容**，
> 上传时可整个排除。
>
> **驱动脚本请先过 `node --check` 再用**：括号失衡时 Node 会把错误报在**下一行**，
> 极易误判（本项目在此栽过跟头，排查被带偏很久）。`_run_wy.py` 已内置这道自检。
>
> **浏览器隔离**：所有脚本都用项目自己的 `_check/*profile`，
> **绝不按「进程名 + 启动时间」批量杀 Edge**——曾因此把用户正在用的浏览器
> 一起强杀了。要清理请用 `_cleanup_edge.py`（它按命令行里的
> `--user-data-dir` 精确识别，且有演练模式）。headless 跑完通常自行退出，
> 多数情况压根不需要清理。

## 已知限制

- **字体**：正文用系统宋体系列（Songti SC / Noto Serif SC / SimSun）。
  若目标设备缺字体会退化到默认衬线，观感略有差异。
- **浏览器能力**：标题的墨色渐变用 `background-clip: text`，
  已提供 `@supports` 降级；不支持时退回纯墨色。
- **存储上限**：`localStorage` 约 5MB。图片素材多时请及时导出备份。
- **未做后端**：无账号、无云同步、无排行榜。跨设备需手动导出／导入。
